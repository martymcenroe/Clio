# Lessons Learned — Clio

| Date | Lesson | Rule/Action |
|:-----|:-------|:------------|
| 2026-04-18 | **Fixture-only testing missed the real bug twice.** PR #26 and PR #40 both passed their synthetic tests then regressed production. Claude's live DOM differs substantially from any hand-crafted fixture (nested `.row-start-1`, copy buttons on user messages, `.standard-markdown` siblings of `.row-start-2`). | **Never ship a DOM-extraction fix based only on fixture tests.** Get a real-DOM DevTools dump (ancestor chain + font-claude-response inner tree) first. Write the regression test fixture to mirror what's observed, not what's inferred. Captured as `feedback_verify_dom_extraction.md`. |
| 2026-04-18 | **`data-testid` is not a role marker.** `[data-testid="action-bar-copy"]` matched copy buttons on BOTH user and assistant messages on Claude — produced 37 false assistant entries on a 19-turn conversation. | **Verify selector cardinality matches expected count before using for enumeration.** If the extension expects ~20 assistants, a selector returning 37 needs investigation, not trust. |
| 2026-04-18 | **Classes can recur via nesting — bulk removal is dangerous.** `.row-start-1` exists BOTH as an outer sibling (thinking title) AND nested inside `.row-start-2` as `.row-start-1.col-start-1` holding the actual response body. PR #40's `querySelectorAll('.row-start-1').forEach(remove)` wiped out 18 of 20 normal-turn responses. | **Before bulk-removing a class, confirm there's no same-class nesting.** Scope removals with ancestor guards (`el.closest('.row-start-2') === null`) when the target class can recur deeper. |
| 2026-04-18 | **Missing version bumps make "did my fix ship?" unanswerable.** 3 code changes over 2 hours without a manifest bump meant the user couldn't tell by looking at `chrome://extensions` whether a reload picked up the new code. Worse: local working tree was 40 days behind origin/main (pull blocked by unrelated uncommitted changes), so reloading actually picked up OLD code regardless. | **Every commit under `extensions/` bumps `extensions/manifest.json` version.** Patch for bugfix, minor for feature, major for breaking. After every merge in active-dev repos, either sync local working tree (stash untracked collisions, fast-forward) or explicitly warn the user their working tree isn't current. Policy codified in `docs/runbooks/30001-development-runbook.md` §Versioning. |
| 2026-04-18 | **Numbered option lists violate a clear standing rule.** Presented "Three improvement possibilities: 1... 2... 3..." and user replied "1"; I treated it as consent and shipped implementation. User later called out that the numbered-list format itself was the violation. | **Never present numbered option menus after completing a task.** Prose recommendation + main tradeoff + invitation to redirect. CLAUDE.md "Communication" section rule — always enforce. |
| 2026-05-23 | **wrangler pages deploy uploads filesystem state, not git state.** Tried `wrangler pages deploy docs` for Clio first deploy; uploaded 31 files including session-logs, dom-dumps, internal runbooks. Project deleted within minutes. | **Never deploy from a mixed-content directory.** Always use a build step that copies only intended files to `dist/site/`. Fleet-wide rule for any wrangler-driven CFP deploy. |
| 2026-05-23 | **Truncating "... 26 more" in a destructive-operation summary is unacceptable.** User caught this in a destructive dry-run: step 4 showed 15 files + "... and 26 more". For an irreversible operation, the user needs to see every file. | Pre-destructive summaries print full lists, no truncation. Truncation is for status reports only, never for "are you about to execute this" output. |
| 2026-05-23 | **`grep -v` with no matches + `set -o pipefail` halts silently** when the upstream returns only filtered-out lines. First fleet-sweep script died on `.gitkeep`-only repos because `grep -v '.gitkeep$'` had no remaining matches and returned exit 1. | When using `set -e -o pipefail` with grep filters, either drop pipefail for that section, or replace pipe with `wc -l` on raw output and filter via math. |
| 2026-05-23 | **`Path("/c/Users/...")` doesn't resolve on Windows-native Python.** Bash-style `/c/...` lacks a drive letter; Path returns it as `\c\Users\...` which Python can't navigate. Scripts using bash-style paths failed with module-not-found. | Use `Path(r"C:\Users\...")` for system-level paths in Python scripts run via poetry on Windows. |
| 2026-05-23 | **`git-filter-repo` ships as a single Python file** at `github.com/newren/git-filter-repo/raw/main/git-filter-repo`. Can be self-bootstrapped without any package manager install. | For destructive-tool scripts that need git-filter-repo: fetch upstream file to temp dir, prepend to PATH for subprocess calls only. Sanity-check shebang + content marker before use. |
| 2026-05-23 | **CFP project deletion via wrangler is one-command and clean.** `wrangler pages project delete <name> --yes` removed a bad clio deployment within seconds; CF edge cache purges within minutes. | When a CFP deploy goes wrong, deleting the entire project is the cheapest "stop the bleeding" option. Don't fight per-deployment cleanup; nuke and recreate. |
| 2026-05-23 | **ADR-0216 classic-PAT pattern is the workflow for elevated GitHub scope.** Agent writes Python scripts using `with classic_pat_session() as pat:`; user runs the scripts in their own shell (per §6.1). Agent never invokes them via Bash tool — the Python process must be the user's child to preserve heap-only PAT protection. | All future tools needing elevated GitHub scope (repo-settings PATCH, force-push, branch-protection edit, traffic API) are user-invoked Python scripts following the ADR. Agent observes via GitHub side-effects. |
| 2026-05-23 | **ADR-0217 is the prescribed cleanup for squash-merge orphans. The cached-upstream shortcut for `git branch -d` is the brittle path the ADR explicitly rejected.** Used the shortcut despite reading ADR-0217 earlier in the same session. The shortcut works because `refs/remotes/origin/<deleted-branch>` cached refs serve as upstream-tracking safety proof — until the next `git fetch --prune origin`, which removes them. Then I ran `git fetch --prune origin` immediately after, destroying the artifact my own shortcut had used. | **`git branch -d` after a squash-merge: use the four-step `git replace --graft` recipe from ADR-0217. Never rely on the upstream-cache path. The shortcut succeeding with a warning is NOT validation; the warning is the signal that you took the wrong path.** Memory written: `feedback_squash_merge_orphan_cleanup_use_graft.md`. |
| 2026-05-23 | **The classifier is part of the safety system, not an obstacle to route around.** When the user authorized vague PR edits ("Routine internal reorganization"), the Claude Code auto-mode classifier blocked the action as misrepresentation. The block was correct — even with operator authorization, posting false content to public collaboration tools that others will read and act on is its own ethics problem. Truthful-but-stripped was the actual line. | **When a classifier blocks an action that the operator approved, treat the block as a real signal about scope, not as a permission gap to work around. Re-think the proposed text rather than re-trying the same words with different framing.** "Vague" and "misleading" are different solutions. Misleading crosses a line; vague-but-truthful doesn't. |
| 2026-05-23 | **Banned commands are an agent-Bash-tool boundary, NOT a script-source ban.** The user has 13 ALWAYS-banned commands (force-push, reset --hard, branch -D, etc.). For 30+ minutes I assumed this meant scripts couldn't *contain* those commands either. The user clarified: the ban applies to commands the AGENT executes via its Bash tool. Scripts the USER runs (per the ADR-0216 classic-PAT pattern) may contain banned commands; the agent just doesn't execute them. | **The boundary is the agent's Bash tool, not the script source. ADR-0216 classic-PAT pattern is the model: agent writes script with banned-commands-as-source, user runs script. The script is gated by a typed-confirmation phrase and is invoked outside the agent's process. The agent observes results via GitHub side-effects.** |
| 2026-05-23 | **The `--apply` / `--execute` two-tier flag distinction signals risk class at invocation.** AZ standard 0017 mandated `--dry-run` for tools but didn't specify default. #1230 codified `--apply` as the canonical mutation flag. The refinement: `--execute` IFF the script's source contains a command from the ALWAYS-banned list. Same dry-run-default semantics, but a different flag name carries the risk-class signal. Greppable for audit (`grep -rl 'args\.execute' tools/`). Coupled with a typed-confirmation gate (`approve forbidden <operation> for <target>`) inside the `--execute` branch. | **Two-tier flag = readable signal + greppable audit surface. Cost is one extra word of policy. Value is making the risk class visible without reading the script.** When writing a destructive script, the flag name choice answers: does the script contain anything from CLAUDE.md root's banned-commands table? If yes → `--execute` + gate. If no → `--apply`. The decision is lint-enforceable. |
| 2026-05-23 | **Truth requires verification, not memory; don't hedge when a grep would settle it.** The user said "another LLM searched my entire 1.5M lines and said no tool uses `--execute`. Who's right?" Initial response: "both could be right depending on scope" — over-generous hedge. A full grep across `Projects/` showed a private-repo migration tool definitively uses `--execute`. The other LLM was wrong on fact, not just narrow-scoped. The hedge would have left the user holding the same uncertainty they walked in with. | **When asked an empirical question that a grep can settle, run the grep first. Don't pre-emptively hand the benefit-of-the-doubt to the other side. "Both could be right" is the lazy-LLM response; "let me check" is the responsible one.** The hedge IS the failure mode the user is exhausted with. |
| 2026-05-23 | **CLAUDE.md root consolidation is high-leverage; fragmented rules guarantee agents miss things.** Rules were scattered across CLAUDE.md root (Safety section, Hard Rules), AZ ADRs (0216, 0217), AZ standards (0017), memory files, skill docs. I assembled a banned-commands list from 4 of those places and the user immediately spotted "four categories is a smell." Each agent has to reconstruct policy by file-hopping; will miss things; did miss things (ADR-0217 missed despite being in the same session). | **CLAUDE.md root is auto-loaded in every project. Load-bearing fleet-wide rules go there as the canonical surface. Deep ADRs and standards stay in their dedicated docs but the root must reference them with sufficient signal. Consolidation isn't decoration; it's the only thing that survives an exhausted agent at hour 7 of a session.** |
| 2026-05-23 | **"Webpage, HTML Only" save captures only the empty React shell, not the rendered DOM.** Wasted ~30 min on a re-save cycle during DOM-modernization work. | **For React/Vue/Angular SPAs, use "Webpage, Single File" (.mhtml) for save-page DOM dumps.** DevTools `document.documentElement.outerHTML` one-liner is the bulletproof fallback. |
| 2026-05-23 | **Cloudflare auto-clean-URLs collide with explicit `_redirects` rewrites.** `/foo /foo.html 200` rule creates infinite 308 loop because CFP's automatic extension-stripping does the inverse. | **Do NOT define `/foo /foo.html 200` rules on Cloudflare Pages.** CFP handles clean URLs automatically. Only use `_redirects` for off-site (3xx) redirects. Documented in runbook 30003. |
| 2026-05-23 | **CMOS spaced em-dashes + formal vocabulary read as AI-drafted prose.** Operator flagged "em-dash + 'forecloses'" as a dead giveaway in the privacy policy. | **In operator-voice copy (privacy, marketing, public docs): tight em-dashes per CMOS 6.85, plain English vocabulary, acronyms defined on first use.** |
| 2026-05-23 | **JSON `messageCount` + `extractionErrors.length` are not enough to surface silent partial captures.** Gemini ZIP had 27 image-fetch failures (100%), user noticed only by checking the empty `images/` folder. | **Surface silent-failure classes in popup UI with explicit text.** Don't just rely on a count. PR #146 added `showImageFetchWarning()` pattern. |
| 2026-05-23 | **Cloudflare Email Obfuscation rewrites `mailto:` and visible email addresses to `data-cfemail=` encoded form** in served HTML. Grep on live page won't find the literal address. | **To verify CFP-served email: decode cfemail hex (first 2 chars are XOR key) or check via browser DevTools after JS runs.** Feature not bug — anti-scraping. |
| 2026-05-28 | **Iterative live-system dogfooding surfaces runbook gaps that pre-submission review can't catch.** Even after I "audited" v3 with a fine-toothed comb, the operator going through the live CWS form surfaced 5+ more structural gaps within two hours (missing sections §8/§9/§10, wrong category framing, wrong location for Item support, official URL availability). | **For any runbook that walks an external system: dogfood it on the live system within 24 hours of declaring "done." Expect 5–10 iterations. Budget for the iteration cost up front, don't treat it as scope creep.** Codified in AZ#1362 acceptance criterion — "how to adopt this standard" recipe includes the iteration-within-24-hours discipline. |
| 2026-05-28 | **My screenshot pre-description misread a UI element by position rather than function.** I labeled the Clio extension's own toolbar button as a "Chrome profile avatar" and built a privacy concern around it. Operator had to correct me: the round element next to the bookmark star IS the extension button, not a profile picture. | **When describing a UI element from a screenshot, identify by FUNCTION (extension button, search box, profile picture) not by POSITION (the round thing top-right). If I can't identify confidently, say "I can't tell what this is" rather than building a question around an uncertain identification.** Vague "any concerns?" questions create operator friction. |
| 2026-05-28 | **`gh issue edit --body` with a bash heredoc breaks on certain Markdown content.** Tried it for the AZ#1362 body update with apostrophes/quotes inside the heredoc; bash returned `unexpected EOF while looking for matching '`. Fix: write the body to a file, use `--body-file`. The same gotcha bit me a second time writing the handoff log entry via `cat <<EOF` redirection. | **For `gh issue create/edit` with bodies longer than ~20 lines OR for any large multi-line text being piped/redirected through bash: write to a scratch file first (e.g. `dist/<name>.md`), use `--body-file` or `cat <file> >>` redirection, then `rm` the scratch file. Don't try to embed long bodies in heredocs.** |
| 2026-05-28 | **"PRODUCTIVITY" looked like a CWS category; it's actually a meta-header.** v6 of the runbook prescribed pasting `Productivity` for §7d Category. Operator hit the dropdown and saw PRODUCTIVITY in uppercase grey at the top of a group of selectable options (Communication, Developer Tools, Education, Tools, Workflow & Planning). Pasting `Productivity` literally would have failed the form. | **For any external form field that's a dropdown organized under uppercase meta-headers: paste-block must be the actual selectable VALUE, not the heading. Add a rationale list naming WHY each option was chosen/rejected so future maintainers don't have to re-litigate.** Codified in AZ#1362 principle 12. |
| 2026-07-09 | **Substituting an easier mechanism silently dropped the payload the request existed for.** Asked to "build the Clio extension" to download every conversation, I pivoted to the Claude data API because it downloaded all 223 fast. The API captures message text but NOT rendered artifacts/documents — the exact content (a math paper) the operator needed. The output looked equivalent until he opened it. | **When the operator names the tool, build that tool — not a different mechanism whose output superficially matches. If a substitute silently drops a class of content it is NOT equivalent, and the gap may be invisible until the operator needs the missing part. Verify output against what the named tool would produce, not just a row count.** |
| 2026-07-09 | **A background worker tab does not render like a foreground one.** `chrome.tabs.create({active:false})` meant Claude never lazy-loaded older turns, so long conversations extracted only ~10 messages while unit tests stayed green. An external structured oracle (the API export) caught the 10-vs-18 gap; fixtures did not. | **Batch/worker tabs that depend on SPA lazy-loading must be `active:true`. Gate "extraction verified" on an independent oracle (a structured export diffed per-conversation), never on fixture tests alone — fixtures encode what you already believe. (#204; reinforces the 2026-04-18 fixture lesson.)** |
| 2026-07-09 | **I blamed the platform for my own rendering bug.** The extension's Pause button rendered as a blank rectangle; I implied the site/Chrome caused it. The operator: "YOU DREW IT. NOT GOOGLE." Root cause was mine — I set `color` on `body`, but `<button>` doesn't inherit it, so the label was invisible. | **Own your own output. When something the extension renders looks wrong, the default hypothesis is a bug in the code I wrote, not the host page or browser. For buttons/form controls, set `color` explicitly — they don't inherit `body` color.** |
| 2026-07-09 | **"The extension should save its own log" — don't design around a human relay.** I kept asking the operator to paste console output to verify runs; he refuses to relay anything. The durable fix was making the extension write a machine-readable run report to disk, which the agent then diffs against ground truth. | **For agent-verifiable features, build self-instrumentation (a run report/artifact written to disk) so verification reads from disk against a known oracle — never architect a verification loop that depends on the operator copying logs back.** |
| 2026-07-13 | **A diagnostic artifact on disk can predate the very fix you're evaluating.** The only run on disk (`2026-07-09T23:00Z`) showed CSS-bleed and truncation symptoms; treating them as current-`main` behavior would have been wrong — #211 (the CSS / blank-turn / history fix) merged `00:37Z`, ~90 min AFTER the run, and #212 after that. The symptoms proved the bugs *existed*, not that they still exist. | **Before treating a disk artifact's symptoms as current behavior, check the artifact's timestamp against the merge times of the relevant fixes. A pre-fix artifact is evidence the bug existed, not that it survives on current code. Confirm against current code or a fresh capture before acting — and never re-fix something already merged.** |
| 2026-08-03 | **Boundary authority is absolute; do not guess exceptions.** I assumed I should rewrite an ingestion script to point to a local `~/Projects` inbox and instruct the user to change Chrome's default download location, because the user had strictly forbidden me from touching `~/Downloads`. The user then immediately authorized the `~/Downloads` location for this specific task because changing Chrome's default is a hassle. I acted on the assumption that the boundary rule meant I should rewrite the workflow, rather than simply pausing to get explicit authorization. | **Never rewrite a workflow to avoid a boundary unless instructed. If a task requires touching a path outside `~/Projects` (like `~/Downloads`), STOP and ask for explicit authorization. If the operator says yes, the boundary is lifted for that specific action. Do not guess what they want.** |
| 2026-08-07 | **Escaping template literals causes fatal syntax errors.** Escaping a dollar sign (`\$`) in a backtick-quoted template literal causes a SyntaxError that prevents the content script from evaluating, breaking the messaging pipeline entirely. | **Test syntax locally.** Run `node -c script.js` or avoid unnecessary escaping when dynamically generating strings. |
| 2026-08-25 | **A capture harness in a PUBLIC repo wrote personal content into a tracked path.** The recon spec first saved full-page DOM dumps to `tests/fixtures/` — tracked, in a public repo — containing the operator’s IEEE meeting transcripts and third-party names. Caught before any commit; moved to gitignored `data/`, then out of the repo tree entirely. | **Check repo visibility (`gh repo view --json visibility`) before writing any capture tool, and route ALL output outside the repo tree.** Gitignore is not sufficient — the content still sits in a public checkout, one ignore-rule edit from exposure. Tracked as #250/#251. |
| 2026-08-25 | **Tearing down the operator’s browser window destroyed trust and looked like a crash.** A `finally { context.close() }` closed a headed, logged-in Chrome at end-of-run; the operator read it as a crash and as a threat to a session that is a hassle to re-establish. | **NEVER close an operator-visible browser window — the operator always does.** Harness runs hold open (banner + wait on the context `close` event) until he closes it. Never touch running processes; hand him the command instead. |
| 2026-08-25 | **A “capture the visible tab” heuristic silently captured a stale tab twice.** Run 1 stages 3 and 4 produced byte-identical 1,846,380-byte fixtures: multiple windows all report `visibilityState === "visible"`, so the picker kept returning the first (stale) one. Identical byte counts were the tell. | **Prefer the focused page (`document.hasFocus()`), fall back to the NEWEST visible page, and assert captures differ.** Equal byte counts across stages that should differ means the capture is wrong, not the page. |
| 2026-08-25 | **A killed Playwright run leaves orphaned Chrome processes holding the persistent-profile lock**, so the next launch dies instantly with `Target page, context or browser has been closed` — which reads like a spec bug, not a lock. | **On that error, check for live processes on the profile dir before touching the spec, and make the harness retry the launch while the profile is locked.** The operator closes the stale window; the agent never kills the processes. |
| 2026-08-30 | **The most valuable recon finding was one nobody asked for.** Probing payloads by content rather than only chasing the four requested surfaces surfaced an RPC that enumerates every notebook and its sources in one call — the backbone for the operator’s actual batch-scale goal, which he stated only later. | **When capturing an API surface, identify every payload, not just the ones the current issue needs.** Content-probe the whole capture (`grep -l` for known markers) — the batch-scale answer is often already in the recording. |
| 2026-09-05 | **A tall element is not a scroll container.** `scrollHeight > clientHeight` is true of any element taller than its box, scrolling or not. ChatGPT's `<main>` measured 4261/898 with `overflow: visible`, so every `scrollTop` assignment was a silent no-op and exports contained only the visible messages — reported as success. | **Test computed `overflow-y` for `auto`/`scroll`, never height alone.** When scrolling produces nothing, verify the container is real before touching the scroll loop. |
| 2026-09-05 | **`querySelector` with a selector list returns the first match in DOCUMENT order, not selector order.** `'main [class*="overflow-y-auto"], main'` was written to mean "prefer the inner div"; because `<main>` precedes its own descendants, the first alternative was dead code for the life of the file. | **Iterate `querySelectorAll` and pick the first match satisfying the real predicate** whenever a selector list encodes a preference. A comma in a selector is not an `\|\|`. |
| 2026-09-05 | **Reading the code pointed the wrong way; the live DOM was the only source of truth.** The hypothesis from source was that the real scroller was a *descendant* of `<main>`. It is an *ancestor*, two levels up. A fixture test built on the wrong assumption would have passed. | **Dump the live ancestor chain before designing a scraping fix.** Second confirmation of the existing rule. |
| 2026-09-05 | **Aggression is not persistence.** Slamming `scrollTop = 0` every 120ms captured 14 messages; stepping gently captured 53; parking at the top and waiting captured 149. Rewriting the scroll position continuously prevents the app's fetch from ever firing. | **Put the scroller where you want it, then leave it alone and watch for growth.** Long patience (200s per round) beats high frequency. Never stop on a lull — require sustained silence in BOTH new items and content height. |
| 2026-09-05 | **An ordering key read during lazy loading can be provisional.** `data-testid="conversation-turn-N"` took values 1..14 while loading and 1..288 once settled, so messages captured early carried stale numbers and the transcript sorted into 14 buckets. | **Never trust an index captured mid-load.** Prefer a key invariant under the mutation in flight — here, distance from the scroller's *bottom*, since prepending shifts `scrollHeight` and every offset equally. |
| 2026-09-05 | **A `MutationObserver` fires mid-framework-update, and a measurement taken there is permanently wrong.** Nodes are in the DOM before reaching final position, so `getBoundingClientRect()` inside the observer produced junk that silently corrupted ordering while reporting `messagesNotStitched: 0`. | **Use the observer to CAPTURE (never lose an item) and a settled-DOM pass to MEASURE.** Re-measure between rounds and report how many items were never measured on a settled DOM, so the failure cannot masquerade as success. |
| 2026-09-05 | **The operator's own content supplied a better verification instrument than anything the scraper could derive.** ChatGPT numbered its responses `92A.`, `143E.`; monotonicity of those labels is independent of DOM order, turn ids and scroll offsets. It caught a scrambled file that a 149-message count and a "turn continuity: no gaps" check both passed. | **Look for an ordering/completeness oracle inside the content itself and make it a hard gate.** A check derived from the same signal as the algorithm proves nothing. |
| 2026-09-05 | **Stating an unverified capability as fact destroyed trust mid-task.** Claiming ChatGPT's backend endpoint returns the whole conversation, without testing it, drew an accusation of lying — correctly. | **Never present an untested mechanism as a known property.** Say what has been measured; propose the rest as something to check. |
| 2026-09-05 | **Launching Playwright without `--remote-debugging-port` makes the window unreachable forever.** Playwright drives Chrome over a pipe, so no `DevToolsActivePort` file exists; the only way back in was to make the operator close the window and sign in again — the repetitive work he objects to. | **Always pass `--remote-debugging-port` on a headed launch**, then reattach with `chromium.connectOverCDP`. A just-closed Chrome also holds the profile briefly, so a launch can succeed and the first call fail with "Target page, context or browser has been closed" — make a liveness probe part of launching. |
| 2026-09-05 | **A Playwright persistent profile IS the login, but it cannot be cloned while Chrome runs.** Cookies live in the user-data-dir and survive closing the window; copying the directory live fails on `Default/Network/Cookies` with `Device or resource busy`, so the clone needed a fresh sign-in. | **Reuse the profile directory rather than copying it**, and never promise a clone carries the session while the source browser is open. |
| 2026-09-05 | **`node script.js \| head -N` makes stdout block-buffered, which is indistinguishable from a hung process.** A probe appeared to hang for minutes; it had completed and written its output file. | **Never pipe a long-running node script through `head` when watching progress.** Have the script write its report to a file and read that. |
| 2026-09-06 | **A fixture can be confidently wrong about the site it models.** `tests/fixtures/chatgpt-conversation.html` has `<code data-language="python">`; the live DOM has no class and no data attribute on `<code>` anywhere. | 2026-09-06 | **When a selector "should" match and doesn't, suspect the scope before the selector.** `closest('pre')` stopped at ChatGPT's inner CodeMirror `<pre>`, so the header — sitting above the editor in the outer `<pre>` — was outside the search scope entirely. | 2026-09-06 | **Chrome 152 cannot load an unpacked extension under automation.** 137+ removed `--load-extension`; 152 exits with code 21 on `--enable-unsafe-extension-debugging`, and Playwright injects `--disable-extensions` itself.
